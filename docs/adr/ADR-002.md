# ADR-002: Dual-Phase Traversal & In-Memory Graph Caching for Vietnamese Kinship Engine

## Status
Accepted (2026-09-21)

## Context
Vietnamese kinship address terms (xưng hô gia phả) are highly intricate, governed by generational distance ($\Delta g$), maternal/paternal lineage ("Chi nội" / "Chi ngoại"), relative seniority, gender, and regional dialects (`bac`, `trung`, `nam`). Traditional tree algorithms (such as binary-lifting LCA or Euler-tour RMQ) are mathematically invalid because genealogy networks are multi-parent directed acyclic graphs (DAGs) with potential endogamy loops (consanguinity). Furthermore, running recursive CTEs in PostgreSQL fails $p95$ latency targets (< 100ms) under large graphs (5,000+ members), while precomputing $O(N^2)$ all-pairs paths requires gigabytes of memory.

## Decision
1. **Per-Family In-Memory Adjacency Graph**: Cache the family DAG in Go memory keyed by `family_id:version`. Reads bypass the database pool completely on warm cache.
2. **Dual-Phase Path Traversal**:
   - **Phase 1 (Blood LCA)**: Ascend directed `parent_child` edges from both members to intersect ancestor sets. Identify all common ancestors, select the minimal-distance Lowest Common Ancestor (LCA) with a depth cap of 12, and extract the blood path `from -> LCA -> to`.
   - **Phase 2 (Affinal Fallback)**: If no blood ancestor is shared, execute an edge-weighted Dijkstra traversal over the combined graph where blood edges cost 10 and spouse edges cost 15. This strictly prevents spouse bridges from corrupting blood paths.
3. **Dynamic Generation Delta**: Generational gap is computed at query time from path edge signs ($\sum \text{parent edges up} - \sum \text{child edges down}$); stored `generation_index` in the database is for UI display only.
4. **Data-Driven Embedded Lexicon**: Store regional kinship lookup tables as JSON assets embedded via Go `embed.FS` (`bac` default with hierarchical fallback).
5. **Bare Text Contract (INV-05)**: Kinship calculation returns raw string terms without formatting or quotation characters.

## Consequences
- **Positive**: Sub-millisecond kinship traversals (~0.04ms for seed fixtures, ~1.8ms for 5,000 members) with low memory footprint (~1.6MB per 5,000 members).
- **Positive**: Complete separation between graph topology algorithms and linguistic dialect dictionaries.
- **Negative**: Requires rigorous cache invalidation on any genealogy mutation (resolved via `family.version` increment).
