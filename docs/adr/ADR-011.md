# ADR-011: Segmented Docker Network Architecture & Multi-Compose Demo Isolation

## Status
Accepted (2026-09-21)

## Context
Deployments must support production operations and isolated demo evaluations on a single server without managed cloud infrastructure or external SaaS dependencies (PROMPT.md §1). The database must be physically protected from public networks, while demo sessions must never touch production volumes, databases, or cookies.

## Decision
1. **Dual-Tier Network Segmentation**:
   - `front-net`: Bridges the Nginx web container and the Go API container.
   - `back-net`: Bridges the Go API container and the PostgreSQL container, configured with `internal: true`.
   - The PostgreSQL port (5432) is NEVER published to the host machine. Only port 3456 (Nginx) is exposed on production.
2. **Mode A Multi-Compose Stack Segregation**:
   - Production stack runs via `deploy/docker-compose.yml` on port 3456 with named volume `pgdata`.
   - Demo stack runs as a separate Compose project via `docker compose -p cgp-demo -f deploy/docker-compose.demo.yml --env-file deploy/.env.demo up -d` on port 3457 with named volume `cgp_pgdata_demo`.
   - The demo stack runs with separate database credentials, distinct internal networks, isolated cookies (`cgp_demo_session`), and distinct JWT secrets and issuers (`cgp-demo`).
3. **Hardened Nginx Reverse Proxy Configuration**:
   - Single entrypoint on port 3456/3457 serving the Vue 3 SPA and proxying `/api/*` to the Go backend.
   - Immutable cache headers (`max-age=31536000, immutable`) for hashed `/assets/`.
   - Service worker `sw.js` and app manifest served with `Cache-Control: no-store`.
   - Upload limit capped at `client_max_body_size 15M` for Excel files.
   - Rate limiting on authentication routes (`/api/v1/auth/*`) at 5 requests/sec with a burst of 10.
   - Self-contained CSP without external font origins.
4. **Minimal Container Footprint**:
   - Go API multi-stage build: `golang:1.22-alpine` builder $\rightarrow$ `alpine:3.20` runtime running as non-root `appuser` (<25MB image size).
   - Embedded database migrations run automatically on API startup.

## Consequences
- **Positive**: Zero database attack surface from public networks.
- **Positive**: Complete physical and logical isolation between production and demo users.
- **Positive**: Instant one-command startup (`docker compose up --build`) without cloud orchestration fees.
- **Negative**: Operators must manage two environment files (`.env` and `.env.demo`) when running both stacks concurrently.
