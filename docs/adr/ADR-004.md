# ADR-004: Bi-Directional Gender Mapping Invariant Across Boundaries (INV-03)

## Status
Accepted (2026-09-21)

## Context
Genealogy domains require unambiguous gender representation for ancestor identification and kinship terminology. Vietnamese UI and Excel documents natively use `"Nam"` (male) and `"Nữ"` (female). Conversely, standard database schemas and international interchange formats utilize canonical lower-case English strings (`'male'`, `'female'`). Inconsistencies between internal database storage, external APIs, and user interfaces lead to data corruption, broken kinship terms, and failed spreadsheet imports.

## Decision
1. **Canonical Database Storage**:
   - The `members.gender` PostgreSQL column enforces `CHECK (gender IN ('male', 'female'))`.
2. **Canonical API Contract**:
   - The REST API represents member gender strictly as `"male"` or `"female"`.
   - The OpenAPI 3.0 specification documents `gender` as an enum `['male', 'female']`.
   - Incoming payloads to `POST /members` and `PUT /members/:id` accept both Vietnamese (`"nam"`, `"nữ"`) and English (`"male"`, `"female"`) case-insensitively, normalizing to canonical `'male'`/`'female'` before persistence.
3. **Boundary Translation Modules**:
   - **Go Backend**: `model.ParseGenderVN()` and `model.ParseGenderAPI()` provide centralized string normalization and bidirectional mapping (`ToVN()`, `ToAPI()`).
   - **Excel Engine**: The import parser accepts `"Nam"` and `"Nữ"` (case-insensitive, trimming whitespace) and converts them to DB canonical `'male'`/`'female'`. Export writes localized `"Nam"`/`"Nữ"` columns.
   - **Vue 3 Frontend**: Adapters `toApiGender()` and `toUiGender()` ensure that user forms display `"Nam"` / `"Nữ"` chips while transmitting `'male'` / `'female'` over the network.

## Consequences
- **Positive**: Uniformity across all system layers: international English standard in database and REST API, natural Vietnamese localization for users and Excel files.
- **Positive**: Strict compile-time and runtime validation prevents invalid gender strings from entering storage.
- **Negative**: Requires explicit mapping code at all boundary adapters (HTTP handlers, Excel import/export, and frontend API client).
