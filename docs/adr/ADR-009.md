# ADR-009: Schema Deltas for Kinship Cache Invalidation & Event Reliability

## Status
Accepted (2026-09-21)

## Context
The architectural synthesis revealed that the baseline database schema outlined in `PROMPT.md §4` lacked essential tracking columns and tables for high-performance in-memory caching and resilient message handling. Specifically:
1. The kinship engine caches family relationship DAGs in memory, but had no mechanism to invalidate cache entries when tree mutations occurred.
2. Magic link authentication required cryptographic storage for single-use tokens.
3. Web Push and email delivery required reliable transaction-decoupled queuing (ADR-008).

## Decision
Introduce three specific schema deltas via PostgreSQL migrations:
1. **Kinship Cache Invalidation Column (`families.version`)**:
   ```sql
   ALTER TABLE families ADD COLUMN version BIGINT NOT NULL DEFAULT 1;
   ```
   Every transaction mutating family membership or relationships (member create/update/delete, edge additions/removals, Excel imports) MUST increment `version = version + 1` inside the same transaction. The kinship engine binds in-memory caches to `family_id:version`.
2. **Transactional Outbox Table (`outbox_events`)**:
   ```sql
   CREATE TABLE outbox_events (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       topic TEXT NOT NULL,
       payload JSONB NOT NULL,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       processed_at TIMESTAMPTZ
   );
   CREATE INDEX idx_outbox_unprocessed ON outbox_events(created_at) WHERE processed_at IS NULL;
   ```
3. **Magic Link Single-Use Token Storage (`magic_link_tokens`)**:
   ```sql
   CREATE TABLE magic_link_tokens (
       token_hash TEXT PRIMARY KEY,
       email TEXT NOT NULL,
       expires_at TIMESTAMPTZ NOT NULL,
       consumed_at TIMESTAMPTZ,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );
   ```
   Only cryptographically secure SHA-256 hashes of generated tokens are stored, preventing credential leakage in the event of database dumps.

## Consequences
- **Positive**: Perfectly coordinated, instant cache invalidation without requiring distributed cache expirations (TTL) or stale reads.
- **Positive**: Full security compliance for magic link tokens and bulletproof outbox queuing.
- **Negative**: Adds schema migrations beyond the initial blueprint, requiring migration verification during API startup.
