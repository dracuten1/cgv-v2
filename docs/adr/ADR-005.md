# ADR-005: Clean Monorepo Architecture & Interface Segregation (D1, D2)

## Status
Accepted (2026-09-21)

## Context
CGP v2 is built as a single Go backend coupled with a Vue 3 SPA monorepo. As business logic expanded across auth, members, kinship, Excel interchange, social feed, and push notifications, naive package organization risked circular dependencies, tight driver coupling (such as `pgx` leaking into domain services), and sprawling god-interfaces. Clear module boundaries and interface segregation were required.

## Decision
1. **Colocated Domain Packages & Central Wiring Hub (D1)**:
   - Domain packages (`auth`, `kinship`, `excel`, `feed`, `push`) encapsulate models, domain services, and ports.
   - HTTP transport handlers are located in `internal/handler/`, bound together in `router.go`.
   - Concrete database implementations live in `internal/repository/{auth,genealogy,social}`.
2. **Interface Segregation via Consumer-Side Ports (D2)**:
   - Domain services and HTTP handlers declare narrow, consumer-side interfaces (e.g. `FamilyRepository`, `MemberRepository`, `ContactStore`, `TxRunner`) instead of depending on monolithic repository structs.
   - Driver independence: domain logic does not import database driver packages (`github.com/jackc/pgx/v5`).
   - A unified database interface (`database.DBTX` exposing `Exec`, `Query`, and `QueryRow`) is satisfied by both `*pgxpool.Pool` and `pgx.Tx`, allowing repository functions to run inside or outside transactions transparently.
3. **Connection Pool Tuning (D3)**:
   - The PostgreSQL pool (`pgxpool`) is configured with `MaxConns: 20`, `MinConns: 2`, `statement_timeout: 5s`, connection lifetime of 1 hour, and idle timeout of 15 minutes, ensuring predictable resource usage and headroom for background jobs.

## Consequences
- **Positive**: Strict decoupling allows testing domain logic in isolation using in-memory mock repositories.
- **Positive**: Elimination of circular package imports across domain boundaries.
- **Positive**: DB connection pool is protected against connection exhaustion under high concurrency.
- **Negative**: Requires adapter glue code (`adapters.go`) to wire concrete repositories to consumer port interfaces.
