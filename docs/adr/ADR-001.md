# ADR-001: Multi-Provider Identity Resolution & Account Linking

## Status
Accepted (2026-09-21)

## Context
CGP v2 replaces legacy single-provider authentication with an extensible multi-provider identity model supporting Zalo, Google, Facebook, email magic links, and an offline mock provider (PROMPT.md F1). Users need to link multiple social logins and contact points (email, phone) to a single family account. However, naive auto-linking introduces severe account takeover vulnerabilities (e.g. unverified OAuth claims claiming another user's email) and race conditions when concurrent logins occur with shared identifiers.

## Decision
1. **Decoupled Identity Model**: Separate `users` (canonical accounts) from `user_identities` (provider credentials) and `contact_points` (verified communication channels).
2. **Resolution State Machine**:
   - Step 1: Match `(provider, provider_subject)` in `user_identities`. If found, touch `last_login_at` and issue session JWT.
   - Step 2: Check for a **strictly verified** contact point claim (`email` or `phone`). Unverified claims NEVER trigger auto-linking.
   - Step 3: If verified contact matches an existing `contact_points` entry for user $U$, auto-link the identity to $U$.
   - Step 4: If verified claims match multiple distinct users (e.g., email belongs to User A, phone belongs to User B), do NOT auto-link. Create an isolated user, flag `conflict_detected: true`, and prompt manual user-initiated merge.
   - Step 5: Otherwise, create a brand-new user with the identity and contact point.
3. **Sole Provider Protection**: A user is forbidden from unlinking their sole remaining login provider, returning `409 Conflict` (`LAST_IDENTITY_CANNOT_BE_REMOVED`).
4. **OAuth Pre-Tx Separation**: Network exchanges with IdPs (token exchange, profile fetch) occur strictly outside database transactions.

## Consequences
- **Positive**: Clean user experience with automatic identity consolidation across Zalo, Google, and Email while preventing account takeover.
- **Positive**: Hard guard against locking users out by preserving at least one login identity.
- **Negative**: Requires careful concurrency control and transaction isolation around contact point lookups and identity insertions.
