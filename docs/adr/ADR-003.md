# ADR-003: Physical Isolation & Fail-Fast Matrix for Mode A Demo Stack

## Status
Accepted (2026-09-21)

## Context
To showcase CGP v2 without requiring users to configure OAuth client secrets or SMTP servers, the system includes a one-click "Dùng thử ngay" (Demo) capability. However, demo sessions must never expose production family trees or leak dummy modifications into production data. Shared-database approaches (e.g. `tenant_id` flags or schema namespaces) are prone to query filtering leaks and accidental data corruption.

## Decision
1. **Physical Stack Segregation**:
   - Production runs via `deploy/docker-compose.yml` on port 3456.
   - Demo runs as an independent Docker Compose project (`-p cgp-demo -f deploy/docker-compose.demo.yml --env-file deploy/.env.demo`) on port 3457.
   - Separate named volumes (`pgdata` vs `cgp_pgdata_demo`), distinct bridge networks, and separate database roles/credentials.
2. **Distinct Session & Security Boundaries**:
   - Production uses cookie `cgp_session` and JWT issuer `cgp-api`.
   - Demo uses cookie `cgp_demo_session` and JWT issuer `cgp-demo`.
3. **Application-Level Containment**:
   - Demo users have `is_demo: true` in `users`.
   - Identity resolution state machine prohibits linking real OAuth providers to demo accounts and vice versa.
4. **Pre-Listen Fail-Fast Matrix (INV-04)**:
   - On startup, the Go binary validates environment configuration before opening the HTTP listening socket (`net.Listen`).
   - If `DEMO_MODE=true` but the database URL matches production, cookie names match, or JWT secrets are shared, the process logs a critical error and terminates immediately with `os.Exit(1)`.

## Consequences
- **Positive**: Zero possibility of demo users corrupting or accessing production genealogy records.
- **Positive**: Complete compliance with invariant INV-04 through automated startup validation.
- **Negative**: Requires maintaining two docker-compose orchestration configurations and double deployment resources when running both stacks on a single host.
